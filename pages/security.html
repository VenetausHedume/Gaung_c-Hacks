Security & Verification Architecture FAQ

To prevent unverified single reports from defaming a store in a public append-only log, the trigger replaces the store's identity with pharmacy_ref = sha256(normalised_licence_or_name || secret_pepper). The secret pepper lives in private_settings with RLS enabled and zero public policies, accessible only to SECURITY DEFINER functions.
When a user or community search calls get_pharmacy_case(p_licence), the database computes the store's pharmacy_ref and counts report_filed entries in the last 90 days grouped by report_type. Only when at least 3 reports of the same type exist does threshold_met become true and reveal pharmacy_name.
